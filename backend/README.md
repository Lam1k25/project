# Backend и аккаунты

## Публикация в интернете (Render)

В корне проекта находится `render.yaml` для Render Blueprint. Чтобы получить
публичную ссылку:

1. Создайте **приватный** GitHub-репозиторий и загрузите туда проект. Файл
   `backend/.env`, базы `*.db`, `.venv` и `node_modules` не добавляйте:
   они исключены через `.gitignore`.
2. В Render выберите **New → Blueprint**, подключите приватный репозиторий
   и подтвердите создание сервисов из `render.yaml`.
3. В настройках сервиса Render укажите секреты `CLOUDFLARE_ACCOUNT_ID` и
   `AI_API_KEY`. Их значения берите в Cloudflare; не добавляйте их в GitHub.
4. Дождитесь успешного Deploy и откройте выданную Render ссылку. Пользователи
   смогут регистрироваться и писать друг другу с любых устройств через эту ссылку.

Файл Blueprint задаёт бесплатные планы. У бесплатного веб-сервиса Render есть
ограничения: он засыпает после периода бездействия, поэтому первый запрос может
загружаться дольше. Бесплатная PostgreSQL-база ограничена по сроку жизни и ресурсам;
по текущим условиям Render бесплатная база удаляется через 30 дней. Для длительного
хранения аккаунтов и переписок перед окончанием её срока нужно
перейти на платный план или экспортировать данные. Бесплатные планы не подходят
для надёжного production-развёртывания. Render может потребовать подтвердить
план и выставить счёт — проверьте условия перед подтверждением.

## Запуск

Установите зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

Для Cloudflare Workers AI откройте `backend\.env` и заполните
`CLOUDFLARE_ACCOUNT_ID` и `AI_API_KEY` своим Account ID и API-токеном.
Остальные настройки уже подготовлены. После этого запустите backend:

```powershell
.\.venv\Scripts\python.exe -m backend.main runserver
```

Сервер откроет мессенджер на `http://127.0.0.1:8000`. Локально база задаётся
переменной `MESSENGER_DATABASE_URL`; по умолчанию используется `backend/test.db`.
В Render соединение с PostgreSQL задаётся через `DATABASE_URL`.

AI Assistant and Russian Text Corrector use LangChain and `ChatOpenAI`.
The assistant answers questions and keeps conversation context; the corrector
focuses on Russian spelling, punctuation, grammar, and word choice while
preserving the original meaning and style. For GLM-4.7 models, reasoning is
disabled for proofreading requests to reduce correction latency.
Модель OpenAI по умолчанию — `gpt-4o-mini`;
её можно изменить переменной `OPENAI_MODEL`. Для Cloudflare модель и адрес API
настроены в `backend\.env`. Для другого OpenAI-совместимого провайдера задайте его
адрес через `AI_BASE_URL`, ключ через `AI_API_KEY`, а имя модели через `AI_MODEL`.

Для локального сервера без авторизации укажите `AI_BASE_URL` и `AI_MODEL`;
если у сервера включена авторизация, также укажите `AI_API_KEY`. Ключи хранятся
только в переменных окружения backend и не передаются браузеру.
Эндпоинт `POST /ai/chat` требует авторизованную сессию и принимает до 20 сообщений
истории с общим ограничением в 12 000 символов.

## Аккаунты и сессии

- Регистрация и вход: `POST /auth/register`, `POST /auth/login`.
- Профиль: `GET /auth/me`, изменение имени и email: `PATCH /auth/me`.
- Смена пароля: `POST /auth/change-password`; при этом старые сессии отзываются.
- Выход: `POST /auth/logout`.
- Для API чатов и списка пользователей требуется bearer-токен из ответа входа.
- Пароли хранятся как PBKDF2-хэши, в базе сессий хранится только хэш токена.

Единая SQLAlchemy-схема объявлена в `models.py`, а подключение и фабрика сессий —
в `database.py`. При запуске существующая `backend/test.db` дополняется полями
авторизации без удаления истории. Ранее созданные записи пользователей без пароля
остаются в базе, но войти в них нельзя; они не показываются как доступные контакты.
Создайте новый аккаунт для работы в мессенджере. Старая корневая `sql_app.db`
больше не используется и автоматически не объединяется с основной базой.

История сообщений сериализуется через Pydantic-схему, а отправитель загружается
одним SQL JOIN; это исключает N+1 запросов при формировании истории диалога.

Перед публичным развёртыванием также нужны HTTPS, подтверждение email и защита
эндпоинтов входа/регистрации от перебора паролей.
